# Proportional Execution

Read this before the intake. Default to a concise run, not a research workshop. Ask no extra mode question. Use a deeper run when the user requests deeper research or a longer transcript.

## Concise run

- Run six turns, preserving direct rebuttals, closed question handoffs, concessions, falsifiers, and safety checks. Add only the optional pair allowed by `references/rules.md`.
- Set the evidence agenda from the user's hypotheses. Verify consequential factual claims, not every adjacent topic. Start with a small set of directly relevant primary sources and expand only when a decision-critical question requires it. Missing private evidence stays unknown rather than triggering an unrelated web investigation.
- Reuse relevant evidence already in the conversation when scope and freshness remain suitable. Recheck time-sensitive laws, eligibility, pricing, and current policy before asserting them. Never reuse an unsupported earlier claim as evidence.
- Produce the scripted turns sequentially as simulated perspectives. Do not run a separate independent model or tool invocation per turn unless the user requests independent execution.
- Keep the visible seven-section readout around 650 to 900 words and the accompanying report around 2,200 to 3,200 words. These are authoring targets, not time guarantees. Extend only to preserve a consequential issue.
- Store each detailed artifact once. Avoid repeating the entire synthesis, metrics, V1, and source discussion in multiple report sections. Reference the shared tables. Retain the actual transcript and complete material objections.
- Leave scores blank. Include the compact rubric once. Load a verdict template only after the user scores or chooses a verdict, and the prototype template only when requested.

## Deeper run

Use the deeper turn budgets and investigate additional decision-relevant sources. Preserve the same intake, six-turn default, optional extension to eight total, and seven-section structure. Greater depth does not automatically increase the turn count. Do not expand mechanically.

## Integrity and latency

Shorten repetition, not essential safety analysis. Never skip verification of a consequential real-world claim for speed. If research cannot resolve a blocker, explain the uncertainty and propose its resolving test.

Do not promise a completion time. Attribute elapsed time to stages only when measured. Waiting for intake answers is separate from execution after intake.
